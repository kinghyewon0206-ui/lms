## 2. 시연에 필요한 공개 범위 — 지금 막혀 있는 것
운영 모드에서는 공개(published)된 강좌만 학생에게 보인다. 진단평가도 승인 전에는 닫혀 있다. 초안 미리보기(`ECONOVA_CONTENT_PREVIEW`)는 운영에서 켜면 앱이 시작하지 않는다.
따라서 **지금 상태 그대로 배포하면 강좌·진단평가가 보이지 않는다.** 선택지는 아래와 같다.

| 선택지 | 방법 | 장점 | 위험·비용 | 권장 |
|---|---|---|---|---|
| **A. 일부 강좌를 사람이 검토·승인·공개** | 소유자가 c01(+c09, 진단평가)을 `/admin/content` 에서 검토·승인 → 릴리스 적용 → 공개 커밋 (`docs/release/release-decision-summary.md` 6장) | 기존 절차 그대로라 새 우회로가 없다. 심사위원이 실제 제품을 본다. 리허설 테스트가 이미 이 경로를 검증함 | 소유자 검토 시간 (c01 체크리스트 기준 강좌당 1~2시간). 공개하면 누구나 볼 수 있다 | **권장** |
| B. 심사위원 전용 미리보기 모드 (새 기능) | 별도 배포 + 접근 코드 + "Draft — not yet reviewed" 표시 + 관리자 기능 없음 + 표본 데이터 표시 | 승인 전 자료로 시연 가능 | 새 접근 경로 = 새 보안 표면. 공개와 분리되어 있어도 사실상 초안을 외부에 보여 준다 → **소유자 승인 필요**. 구현·테스트 반나절 이상 | 승인 시에만 |
| C. 보호된 배포 + 녹화 | Vercel Authentication "All Deployments"(소유자만 접근)에서 소유자가 시연하고 녹화 | 외부 노출 0 | 심사위원이 직접 써 볼 수 없다 | A 의 보조 수단 |
| D. 로컬 시연 | 대회장에서 노트북 5071 로 시연 | 노출 0, 네트워크 불필요 | 원격 심사 불가 | 대비책 |

B 를 고를 경우의 설계 원칙 (구현하지 않음):
- 공개 상태와 별개의 플래그로 두고, `published` 를 바꾸지 않는다.
- 정답 키·해설을 미리 보여 주지 않는다 (채점은 서버에서만).
- 관리자 화면·승인 버튼에 접근할 수 없게 한다.
- 접근 코드는 환경변수로 두고 대회 뒤 삭제한다.
- 모든 화면에 "Competition preview — content not yet reviewed by a human" 을 표시한다.
- 실제 학생 데이터는 쓰지 않는다. 표본 데이터에는 표본이라고 표시한다.

## 3. 접근 계획 (권장안 A 기준)
1. 소유자: c01·c09·진단평가 사람 검토·승인 (AI 검토는 승인이 아니다).
2. 공개 커밋 → 테스트 → 피처 브랜치 푸시 (main 병합 없음).
3. Vercel 첫 배포는 Deployment Protection "All Deployments"(소유자만) 상태로 확인.
4. 확인이 끝나고 소유자가 승인하면 "Standard Protection" 으로 내려 운영 도메인을 공개한다. 심사위원은 Google 또는 이메일로 가입한다.
5. 대회 뒤: 공개 유지 여부 결정, 심사위원 계정·데이터 정리 정책 결정.
