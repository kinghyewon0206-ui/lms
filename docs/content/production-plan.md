출처 후보는 **아직 확인하지 않은 목록**이다. 장 번호·URL 은 초안을 쓸 때 실제 페이지를 열어 확인하고, 확인 못 한 것은 `unverified` 로 두고 인용하지 않는다.
수치가 필요한 사례는 c02 처럼 "가상의 예" 로 쓰고, 실제 통계는 출처를 확인한 경우에만 쓴다 (매달 바뀌는 지표는 정의만 요약).

## 2. 강좌 하나를 만드는 순서 (c02 와 같은 품질 기준)
1. 출처 확인: 레슨마다 1~3개 열어 제목·저자·날짜·라이선스·관련 내용을 확인 → `sources.json` 에 `verification.method` 와 함께 추가.
2. 레슨 자료 3개 (`content/lessons/cNN-lX.json`): 학습목표 3개, 핵심 개념 4~7개(출처 연결), 하·중·상 설명(개념 깊이를 다르게),
   단계별 풀이 예제(자동 검산 `check` 포함), 필요한 경우 그래프, 실제 사례(출처), SDG 사례(선택지 3개 × 편익·비용·가정 + 토론 질문), 핵심 정리.
3. 형성 퀴즈 3개 × 5문항: 학습목표·개념·난이도 표시, 수치형 최소 1문항. **정답 위치를 a~d 에 고르게**, 절대 표현 오답 금지, 레슨 예제 수치 재사용 금지.
4. 최종 평가 10~12문항 (세 레슨 고르게), 재응시 3회, 합격 기준은 `proposed` 로만.
5. 정답 키: 비공개 폴더에 `split` 으로 분리 (`*.answers.json`), 공개 파일에는 정답·해설 없음.
6. 검사: `flask --app app check-content`, `check-public-files`, 전체 테스트, 수치형 답 재계산, 정답 위치 분포 확인.
7. 교사용 검토 문서: `flask --app app review-package cNN` (비공개 폴더).
8. 사람 검토·승인 → 릴리스 계획 반영 → 공개 커밋 → 정답 키 Secret Files.

## 4. 하지 않는 것
- 출처를 지어내거나, 열어 보지 않은 출처를 `verified` 로 표시하지 않는다.
- AI 가 승인·공개하지 않는다 (로더가 AI 승인 기록을 거부한다).
- 출처 본문(특히 OpenStax)을 옮기거나 번역해 싣지 않는다. 개념은 새로 쓰고 출처는 링크한다.
- 새 시뮬레이션·새 기능은 강좌 콘텐츠와 따로 승인받는다.
