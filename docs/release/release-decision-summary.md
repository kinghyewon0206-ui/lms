# ECONOVA 출시 결정 요약 (소유자용, 2026-11-21)

## 2. 품질 근거 (가장 강한 것부터)
1. **두 번의 독립 풀이:** 강좌마다 편집자와 다른 AI 검토자가 정답을 보기 전에 모든 문항을 직접 풀었다. 처음 검토에서 불일치 0, 2차 수정 뒤 123문항 재풀이에서도 불일치 0.
2. **숫자 재계산:** 모든 예제·그래프·정답 키·해설 숫자를 다시 계산했다(오류 0). 숫자 문항은 R1~R5 허용 오차 규칙과 경계 회귀 테스트로 고정.
3. **확인된 오류 수정:** 방향 오류, 한계·총량 혼동, 빠진 가정, 정의 오류, 과도한 단정 등을 강좌마다 고쳤다 (`docs/content/review/changes/`).
4. **자동 검사:** 영어 전용, 구조·정답 키 정합, 공개 파일 정답 노출 0, 학생 접근 차단, 승인≠공개 분리, 실제 c01·c09 콘텐츠로 공개 리허설(임시 복사본)까지 통과.

## 3. AI 검토로 해결할 수 없는 위험 (사람이 판단해야 함)
- **출처 신뢰:** AI 가 페이지를 열어 확인했지만, 사람이 같은 페이지를 보고 인용이 맞는지 확인한 적은 없다 (111개).
- **교육 현장 적합성:** 학생 수준·학습 시간·문화적 맥락 적합성은 실제 학생 자료 없이 검증되지 않는다.
- **논쟁적 정책 서술의 균형:** 최저임금·재분배·무역 정책은 "모형 예측 + 증거는 논쟁 중"으로 썼다. 균형 판단은 사람 몫이다.
- **정책 값:** 합격 기준 70%·재응시 3회, 진단 추천 기준 40%/75%, c09 루브릭 — 학교 정책 결정이다.
- **AI 끼리의 일치는 사실의 증거가 아니다.** 같은 모델 계열의 공통 맹점이 있을 수 있다.

## 4. 남은 교육 쟁점에 대한 AI 판단 (기록)
| 쟁점 | 판단 | 이유 |
|---|---|---|
| 일부 평가에 상급 문항이 0~1개 | **수용 가능 (출시 차단 아님)**, 나중 개선 권장 | 난이도 태그는 실제 인지 부담 기준으로 매겼다. 평가는 레벨과 무관하게 모든 학생이 같으므로 상급 위주면 초급 학생에게 불공정하다. 상급 도전 문항은 별도 선택 기능으로 나중에 추가 권장 |
| c04 이 경기 순환·안정화 정책을 다루지 않음 | **수용 가능** | 강좌 설명·목표는 측정·성장·물가만 약속하고 레슨이 그것을 정확히 가르친다. "Stability" 는 물가 안정 맥락. 경기 순환 레슨 추가는 범위 확장이라 다음 릴리스 후보 |
| c03 탄소세 시뮬레이터의 설명용 값 | **수용 가능** | 모든 레벨·위젯에 "설명용 가상 값, 실제 탄소 가격과 비교 금지"와 단위 환산을 명시. 톤 단위로 바꾸는 시뮬레이터 개선은 나중 |
| 진단 추천 기준 잠정값 | **출시 차단 아님 (선택 기능)** | 추천은 제안일 뿐이고 화면에 잠정값이라 표시된다. 진단평가는 승인 전에는 운영에서 닫혀 있다. 승인 시 기준을 "잠정"으로 유지하는 것을 권장 |
| c09 루브릭 잠정 | **c09 공개에만 차단** | 로더가 승인되지 않은 루브릭의 c09 공개를 막는다. 루브릭은 기준별 서술·가중치 합 100·단계 연결이 내부적으로 일관됨 |

## 5. 이번에 찾아 고친 릴리스 절차 결함 (리허설에서 발견)
1. 승인 반영(`content-release-apply`) 뒤 강좌 JSON 의 레슨·퀴즈·최종 평가·캡스톤 상태 칸이 갱신되지 않아 **카탈로그 전체가 열리지 않던 문제** → 반영할 때 함께 갱신.
2. 평가를 승인해도 문항별 상태가 draft 로 남아 **승인된 평가가 로드되지 않던 문제** → 평가 승인 = 그 문항 전체 승인으로 기록.
3. 위 상태 칸과 공개 결정이 승인 지문을 바꾸지 않도록 지문 계산에서 제외 (다른 승인이 무효가 되지 않게).
4. 비공개 원본 도구가 승인된 평가를 draft 원본으로 덮어쓰지 않도록 막음.
회귀 테스트: `tests/test_release_mechanism.py`, `tests/test_release_rehearsal.py`(실제 키 필요).

## 6. 출시 결정에 필요한 소유자 행동 (순서)
1. **강좌별 사람 검토·승인** (`/admin/content`, 체크리스트 `docs/content/review/c01-checklist.md` 방식) — 최소 출시 단위는 강좌 하나.
2. **출처 확인**: 그 강좌가 인용한 출처만 열어 확인하고 Source 항목에서 승인.
3. **합격 기준·루브릭·진단** 정책 승인 (해당 시).
4. 릴리스 계획 내려받기 → `content-release-apply` → 강좌·레슨 `status` 를 `published` 로 바꾸는 공개 커밋 → `check-content`·테스트.
5. 운영 준비(아래 7장)를 마친 뒤 `docs/deployment-econova.md` 순서로 Render `lms` 교체.
