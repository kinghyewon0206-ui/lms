### 남은 작업 (강좌별)
- **c01, c03~c08**: 레슨 3개의 학습자료·형성 퀴즈·최종 평가(+합격 기준)를 새로 작성해야 한다 (Phase 8A 범위 밖).
- **c02**: 아래 체크리스트로 사람 검토 → 관리 화면에서 검토 결정 → 릴리스 계획 반영 → 정답 키 운영 배치 → 공개 리허설.
- **c09**: 레슨 학습자료·퀴즈 작성, 캡스톤 안내·루브릭(가중치 포함) 사람 검토. c09 의 레슨 요구 조건이 `material + quiz` 이므로
  퀴즈를 만들지 않을 거라면 요구 조건을 바꿀지 사람이 결정해야 한다.

## 2. c02 상세 검토 체크리스트

검토자는 관리 화면에서 대상별로 "검토 시작 → (확인) → 승인 또는 수정 요청" 을 남긴다. 승인은 내용 지문에 묶이므로,
검토 중 내용을 고치면 다시 검토해야 한다.

### 2.1 레슨 1 — 수요와 공급 (`lessons/c02-l1.json`)
- [ ] 학습목표 3개가 레슨 내용·퀴즈와 맞는가
- [ ] 핵심 개념 7개(수요, 수요량, 수요 법칙, 공급·공급량, 공급 법칙, 곡선 위 이동 vs 곡선의 이동, 이동 요인)의 정의가 정확한가
- [ ] 난이도별 설명(하·중·상 각 3구역)이 수준에 맞고 서로 모순되지 않는가
- [ ] 풀이 예제 3개(수요표 읽기 / 이동 구분 / 선형 수요함수 계산)의 숫자와 풀이 단계 (계산은 코드로 재검증됨 — 서술이 맞는지 확인)
- [ ] 그래프 `c02-l1-g1` 의 축·이름표·균형점 설명
- [ ] 실제 사례 "날씨와 농산물 공급" 에 확인되지 않은 수치가 없는가
- [ ] SDG 2 사례(가뭄과 곡물 시장)의 세 가지 정책 대안이 편향 없이 편익·비용·가정으로 서술됐는가
- [ ] 출처: OpenStax 3.1·3.2, UN SDG 2 — 본문을 복제하지 않고 요약·링크만 했는가
- [ ] 연결된 수요·공급 시뮬레이션 안내 문구

### 2.2 레슨 2 — 시장 균형과 가격 결정 (`lessons/c02-l2.json`)
- [ ] 개념 4개(균형, 초과공급·초과수요, 4단계 분석, 가격 상한·하한)
- [ ] 난이도별 설명(각 4구역), 예제 3개(표에서 균형 / 비료 값 상승 4단계 / 가격 상한 부족량)
- [ ] 그래프 `c02-l2-g1`, 실제 사례 2개(임대료 상한, 농산물 가격 지지) — 일반화가 지나치지 않은가
- [ ] SDG 2·12 사례(식량 가격 급등: 상한 vs 직접 지원 vs 공급 지원)
- [ ] 출처: OpenStax 3.1·3.3·3.4, UN SDG 2·12

### 2.3 레슨 3 — 가격 탄력성과 식량 시장 (`lessons/c02-l3.json`)
- [ ] 개념 5개(가격 탄력성, 탄력적·비탄력적·단위탄력적, 중간점 방법, 총수입, 식량 수요의 비탄력성)
- [ ] 예제 3개(간단 계산 / 중간점 방법 / 탄력성과 총수입) — 반올림·부호(절댓값) 안내
- [ ] 그래프 `c02-l3-g1`, 실제 사례 2개(풍작과 농가 수입, 국제 식량 가격 지표 — **수치 인용 없음** 확인)
- [ ] SDG 2·12 사례(비탄력적 수요와 가격 변동성, 음식물 쓰레기). UNEP 자료는 미확인이라 인용하지 않았는지 확인
- [ ] 출처: OpenStax 5.1·5.3, UN SDG 2·12, FAO 식량가격지수, World Bank 식량안보 업데이트 — 정의만 요약, 수치 미인용

### 2.4 진단평가 (`content/diagnostic.json`, 12문항, 6영역)
- [ ] 영역(경제 용어·희소성과 기회비용·수요와 공급·그래프 해석·간단한 계산·정책과 상충관계)별 2문항이 고등학생 입문 수준에 맞는가
- [ ] 정답·해설은 비공개 검토 문서에서 확인 (그래프 균형 가격·균형 거래량·비율 문항은 코드로 재검증됨)
- [ ] 난이도 추천 기준 40% / 75% — 임시 값을 유지할지, 학생 데이터 확보 전까지 "참고용" 안내로 충분한지 결정

### 2.5 형성 퀴즈 3개 (각 5문항, 재응시 제한 없음)
- [ ] 각 문항이 표시된 학습목표·개념을 실제로 측정하는가, 난이도(하·중·상) 분류
- [ ] 오답 선택지가 그럴듯하되 모호하지 않은가 (정답이 둘로 읽히지 않는가)
- [ ] 수치형 문항의 허용 오차와 단위 안내
- [ ] 정답·해설은 비공개 검토 문서에서 확인 (공개 파일에는 없음)

### 2.6 최종 평가 (`c02-final`, 8문항, 최대 3회)
- [ ] 레슨 3개를 고르게 다루는가, 형성 퀴즈와 문항이 지나치게 겹치지 않는가
- [ ] 재응시 3회와 "가장 높은 결과 기록" 정책
- [ ] **합격 기준 70%(제안값)**: 8문항 기준 6문항(75%)부터 합격 — 의도한 기준인지 확인. 승인은 '합격 기준' 대상으로 따로 남긴다

### 2.7 출처와 저작권
- [ ] OpenStax(CC BY-NC-SA 4.0): 비영리·출처 표시·동일 조건. **OpenStax 는 LLM 학습 목적 이용을 서면 허락 없이 금지한다고 고지**
  — ECONOVA 는 본문을 복제하지 않고, AI 튜터에는 출처 목록 정보만 보낸다. 이 해석이 충분한지 사람이 확인
- [ ] UN·FAO·World Bank: 이용 약관에 따라 짧은 요약·링크만, 바뀌는 수치는 인용하지 않음
- [ ] 모든 문항은 새로 작성했다는 기록이 맞는지 (교재 문항 복제 없음)

### 2.8 검토 뒤 절차 (사람 승인 필요)
1. 관리 화면에서 대상별 결정 기록 (레슨 자료 3, 퀴즈 3, 최종 평가 1, 합격 기준 1, 진단평가 1, 강좌 설명 1).
2. 릴리스 계획 내려받기 → 개발 환경 `content-release-apply --dry-run` → 반영 → `check-content`·테스트·diff 검토 → 커밋.
3. 운영 Secret Files 에 c02 정답 키 4개·진단평가 키 배치 → `check-content` 의 "정답 키 확인".
4. 강좌 JSON 의 레슨·강좌 `status` 를 published 로 바꾸는 것은 별도 결정 (공개 리허설 뒤).
